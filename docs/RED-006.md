# RED-006 Configurar pipeline CI

Backlog: P0, M, depende de RED-002 a RED-005. Aceite: “PR/branch executa lint, typecheck e testes.”

Implementação: GitHub Actions em .github/workflows/ci.yml, para push em branches, pull_request e execução manual. Job Linux com Node 24 e pnpm 10.28.1, instalação congelada, check:env, formatação, lint, tipos, testes, build e smoke HTTP de produção local.

Actions oficiais fixadas por SHA, permissões mínimas contents: read, credenciais não persistidas e limite de 15 minutos. Push e PR possuem grupos de concorrência distintos para que ambos possam ser verificados no mesmo commit. Nenhum segredo ou credencial de serviço é exigido.

A CI verifica o código; a integração Git/Vercel preservada publica o site. Não há token Vercel ou etapa de deploy no workflow. A CI não bloqueia automaticamente merges ou publicações: não foram alteradas proteções de branches nem deployment checks.

Para comprovar o aceite, enviar a branch autorizada, abrir um PR, observar as execuções e seus jobs. Somente integrar à main após os checks passarem, dentro da autorização do usuário. Uma execução pendente, bloqueada ou falha deve ser relatada como tal.

Validação local: YAML analisado, gatilhos e permissões conferidos; check:env, formatação, lint, tipos, oito testes, build e smoke HTTP passaram. A execução real depende do envio autorizado e será registrada no relatório de entrega.
