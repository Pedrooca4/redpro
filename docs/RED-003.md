# RED-003 Configurar lint e formatação

Backlog: P0, tamanho S, dependência RED-001. Aceite literal: “Lint executável por script e sem erros na base.”

## Entrega

O ESLint existente mantém os presets Next.js Core Web Vitals e TypeScript. A configuração eslint-config-prettier vem por último para desativar somente regras de estilo conflitantes com o formatador. O comando lint falha também quando há avisos; lint:fix oferece correções automáticas.

Prettier é dependência de desenvolvimento com versão exata e lockfile. format aplica o padrão; format:check verifica sem modificar os arquivos. Configuração: dois espaços, aspas duplas, ponto e vírgula, vírgulas finais, largura de referência 100 e fim de linha LF. EditorConfig e Git padronizam os finais de linha em Windows e Linux.

Build, dependências, arquivos gerados, variáveis de ambiente e lockfile estão excluídos da formatação. A base de fontes, configuração e Markdown foi formatada. Não foram alterados fluxos, contratos de API, variáveis ou serviços externos.

## Validação

Verificados: Prettier check passou; ESLint passou sem erros ou avisos; next typegen e tsc --noEmit passaram; oito testes existentes passaram; build de produção passou. Smoke HTTP verificou /, /status, /api/health e uma rota inexistente.

A comparação dos 16 arquivos em src, tests e scripts confirmou igualdade com o resultado do Prettier aplicado ao commit anterior. Não houve alteração manual de lógica nesses arquivos.

## Limites

Não implementa pipeline CI (RED-006), hooks de commit ou funcionalidades futuras. ESLint 9.39.5 foi mantido por compatibilidade com os plugins atuais do Next.js; a instalação pode informar sua descontinuação, sem que isso seja um aviso de lint do código.
