**Estado: base verificada localmente; envio remoto e publicação pendentes de autorização.**

## Objetivo e aceite

O backlog define a RED-001 como P0, tamanho S, sem dependências: **“Aplicação inicia; estrutura inicial commitada; README explica execução.”** O usuário já possui um repositório `redpro`; a entrega deve reutilizá-lo após identificação e autorização, preservando seu conteúdo.

## Escopo desta entrega

- Projeto Next.js/TypeScript com execução e compilação reproduzíveis.
- Página inicial mínima verde e preta, com navegação real e indicação dos recursos futuros.
- Página `/status` e endpoint `/api/health`, limitado à saúde do processo web.
- Preparação dos clientes e das variáveis públicas do Supabase.
- README e instruções de publicação na Vercel.

Não há chat simulado, catálogo fictício ou comunidade com dados de demonstração apresentados como produção. IA, fontes RAG, contas, persistência, biblioteca e comunidade permanecem pendentes.

## Decisões

1. Usar Next.js 16.4.3, App Router, TypeScript, React, Tailwind CSS 4 e Lucide. Usar pnpm e recomendar Node.js 24, com mínimo 22.12.
2. Preparar Supabase conforme a escolha explícita do usuário. Ausência de configuração não deve impedir a apresentação pública inicial; os serviços externos não são declarados conectados.
3. Preparar Vercel com fluxo Git e Preview primeiro. Não publicar por outra plataforma nem enviar automaticamente à branch de produção.
4. Manter a interface honesta sobre a fase de construção. Links e ações disponíveis devem ter uma finalidade real.
5. Preservar a distinção entre saúde do processo e prontidão dos serviços: `/api/health` não é teste de Supabase, autenticação, banco ou IA.
