# ADR-006 Autenticação gerenciada

Estado: aceita para implementação futura com Supabase Auth.

## Contexto e decisão

A arquitetura exige identidade e autorização no servidor por recurso. A escolha gerenciada reduz código próprio para credenciais e recuperação. O Supabase é coerente com a plataforma já escolhida pelo usuário; os clientes preparados não constituem autenticação funcional.

## Alternativas e consequências

Implementar senhas e sessões do zero aumenta riscos. Uma biblioteca madura ou outro provedor continua alternativa caso haja necessidade comprovada, mediante revisão deste ADR. Supabase Auth exigirá configurar ambiente, sessão, refresh, perfil, políticas e testes de ownership.

## Estado real e sequência

Sem cadastro, login, sessão, perfis ou autorização implementados. RED-011/012 preparam dados; RED-013 define users/profiles; RED-026 integra auth. A interface não decide permissões; futuras rotas deverão validar identidade no servidor. Chave publicável não substitui RLS, ownership ou validação de sessão.

Nenhuma credencial foi solicitada ou alterada neste ADR.
